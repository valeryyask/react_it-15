1. ЧТО СДЕЛАНО (КРАТКО)
--------------------------------------------------------------------------------
Одностраничное веб-приложение (SPA) для агентства недвижимости:

  - страница АВТОРИЗАЦИИ (/login) — вход по логину и паролю через Redux Thunk;
  - страница РЕГИСТРАЦИИ (/register) — создание нового аккаунта;
  - страница ОБЪЕКТОВ НЕДВИЖИМОСТИ (/) — таблица объектов с добавлением и удалением строк,
    индикаторами загрузки (спиннерами) и сводкой статистики (StatsBar);
  - страница РИЕЛТОРОВ (/agents) — вторая форма: расширенная таблица на библиотеке
    TanStack Table с сортировкой, фильтрацией/поиском, постраничной навигацией и
    загрузкой с публичного REST API;
  - навигация (Nav), которая динамически меняется в зависимости от авторизации;
  - глобальные и локальные спиннеры загрузки (LoadingOverlay, LoadingBlock, LoadingButton).

Технологии:
  - React 19 — построение пользовательского интерфейса;
  - Vite — сборщик и быстрый локальный сервер разработки (HMR);
  - React Router 7 (react-router-dom) — маршрутизация между страницами;
  - Redux Toolkit (@reduxjs/toolkit, react-redux) — централизованное хранилище состояния,
    слайсы, createAsyncThunk, мемоизированные селекторы createSelector (Reselect);
  - TanStack Table (@tanstack/react-table) — headless-таблица с сортировкой и пагинацией;
  - JavaScript (ES6+), ООП (модели и сервисы с инкапсуляцией).

2. ЗАДАНИЕ И КАК ОНО ВЫПОЛНЕНО
--------------------------------------------------------------------------------
Основные требования:
  1. Объект с данными об аккаунтах пользователей.
     -> Файл src/services/AccountService.js. Класс AccountService хранит список
        аккаунтов в приватном поле (#accounts), реализует методы authenticate и register.
        Сам аккаунт описывает модель Account (src/models/Account.js).

  2. Организация хранения авторизованного пользователя и данных в Redux Toolkit.
     -> Файл src/store/authSlice.js (хранит user, status, error),
        src/store/propertiesSlice.js (хранит items, status, error, isAdding, deletingIds),
        src/store/agentsSlice.js (данные второй формы).

  3. Маршрутизация с защитой страниц (Protected Routes).
     -> Файл src/App.jsx. Неавторизованный пользователь при попытке перейти на "/"
        или "/agents" перенаправляется на "/login" через <Navigate to="/login" replace />.
        После успешного входа navigate('/') переводит на каталог недвижимости.

  4. Асинхронные действия (Thunk), спиннеры и обработка ошибок.
     -> Использован createAsyncThunk в слайсах. Спиннеры привязаны к статусам pending:
        полноэкранный LoadingOverlay для авторизации, локальный LoadingButton
        для добавления/удаления (по конкретному id), AsyncContent для загрузки таблиц.

3. КАК ЗАПУСТИТЬ
--------------------------------------------------------------------------------
Требуется Node.js (версии 18+ или 20+).

  cd frontend
  npm install        # установка зависимостей
  npm run dev        # запуск сервера разработки Vite (http://localhost:5173)
  npm run build      # сборка проекта в папку dist
  npm run preview    # предпросмотр собранной версии
  npm run server     # запуск вспомогательного mock-сервера Express (порт 3001)

Тестовые аккаунты:
  логин: admin   пароль: admin123   (имя: Администратор)
  логин: user    пароль: user123    (имя: Пользователь)
  (также доступна регистрация любого нового аккаунта на странице /register).

5. КАК РАБОТАЕТ ПРИЛОЖЕНИЕ (ОБЩАЯ СХЕМА)
--------------------------------------------------------------------------------
1) Браузер загружает index.html и запускает src/main.jsx.
2) createRoot монтирует приложение в <div id="root">, оборачивая App в Provider
   (Redux) и BrowserRouter (React Router).
3) В App.jsx селектор selectCurrentUser получает текущего пользователя из state.auth.
4) Если пользователь авторизован, Nav отображает имя и ссылки "Объекты" и "Риелторы",
   а роутер открывает HomePage или AgentsPage.
5) Если не авторизован, роутер перенаправляет с защищённых маршрутов на LoginPage.
6) Все асинхронные операции идут через Redux createAsyncThunk с эмуляцией задержки,
   активируя локальные спиннеры в соответствующих компонентах.


--------------------------------------------------------------------------------
6. REACT: КОМПОНЕНТЫ, JSX, PROPS
--------------------------------------------------------------------------------
- КОМПОНЕНТ — чистая функция, возвращающая JSX. Имя всегда с заглавной буквы.
- JSX — расширение синтаксиса JavaScript, компилируемое в вызовы React.createElement.
  Особенности: className вместо class, camelCase для обработчиков (onClick, onChange),
  вставки выражений через фигурные скобки {expression}.
- PROPS — входные параметры компонента, передаваемые родителем (read-only).
- УСЛОВНЫЙ РЕНДЕРИНГ — тернарные операторы {user ? <A /> : <B />} и логическое И {error && <ErrorMessage />}.
- СПИСКИ И КЛЮЧИ — при отрисовке через map каждому элементу задаётся уникальный key={item.id},
  позволяющий виртуальному DOM (Virtual DOM) точно определять добавленные и удалённые узлы.


--------------------------------------------------------------------------------
7. ХУКИ (ПОДРОБНО)
--------------------------------------------------------------------------------
Правила хуков: вызываются только на верхнем уровне функционального компонента
(не в if, не в циклах, не во вложенных функциях).

- useState — локальное состояние компонента (значения полей ввода в формах, сортировка таблицы).
- useEffect — побочные эффекты (запуск fetchProperties / fetchAgents при монтировании страницы).
- useNavigate — программная навигация (переход на "/" после логина).
- useId — генерация уникальных HTML-идентификаторов для связи label и input в EntityForm.
- useDispatch / useSelector — хуки React-Redux для отправки action'ов и чтения state.


--------------------------------------------------------------------------------
8. REACT ROUTER (ПОДРОБНО)
--------------------------------------------------------------------------------
- <BrowserRouter> — провайдер контекста маршрутизации на основе HTML5 History API.
- <Routes> и <Route> — декларативное сопоставление URL-пути (path) и компонента (element).
- <NavLink> — ссылка в меню с автоматическим добавлением класса "active".
- <Navigate to="/login" replace /> — декларативный редирект для защиты маршрутов.


--------------------------------------------------------------------------------
9. STATE И REDUX TOOLKIT
--------------------------------------------------------------------------------
Архитектура Redux:
- Единственный источник правды (Single Source of Truth) — store.
- Слайсы (createSlice):
  1) authSlice — пользователь (user: { login, name }), статус входа, ошибки;
  2) propertiesSlice — список объектов, индикаторы isAdding и deletingIds (массив id,
     удаляемых в данный момент);
  3) agentsSlice — список риелторов, загрузка по REST API, добавление, удаление.
- createAsyncThunk генерирует экшены pending, fulfilled, rejected.
- Мемоизация (createSelector): селекторы selectPropertiesStats и selectAgentsStats
  кэшируют вычисления (сумму цен, площадей) и не пересчитываются, если ссылка
  на массив не изменилась. Селектор selectIsPropertyDeleting параметризован id записи.


--------------------------------------------------------------------------------
10. ДАННЫЕ (МОДЕЛИ И СЕРВИСЫ, ООП)
--------------------------------------------------------------------------------
Принципы ООП:
- Инкапсуляция: приватные поля (#accounts, #properties, #nextId) защищены от прямого
  изменения извне. Доступ только через методы сервиса.
- Абстракция: компоненты и thunk'и работают с контрактом сервиса (all, add, delete),
  не завися от внутреннего формата хранения.
- Синглтон: создаются и экспортируются единые экземпляры propertyService и accountService.

12. ПОШАГОВЫЕ СЦЕНАРИИ РАБОТЫ
--------------------------------------------------------------------------------
1. Вход: неавторизованный пользователь попадает на /login -> ввод admin/admin123 ->
   dispatch(loginUser) -> появление оверлея загрузки -> сохранение пользователя ->
   перенаправление на "/".
2. Каталог: HomePage диспатчит fetchProperties -> AsyncContent показывает спиннер ->
   отображается сводка StatsBar и таблица объектов.
3. Добавление объекта: заполнение полей AddPropertyForm -> кнопка "Добавить" крутит
   спиннер (isAdding) -> объект появляется в таблице, StatsBar мгновенно пересчитывает сумму.
4. Удаление объекта: нажатие "Удалить" -> кнопка конкретной строки крутит локальный
   спиннер (deletingIds включает этот id) -> строка удаляется из state.
5. TanStack Table: переход на /agents -> загрузка риелторов по сети -> поиск по имени
   через toolbar -> сортировка кликом по заголовкам -> листание страниц 5/10/20.
6. Выход: клик "Выйти" в Nav -> dispatch(logout) -> редирект на /login.

13. VITE И СБОРКА
--------------------------------------------------------------------------------
Vite использует ES-модули в браузере в dev-режиме, обеспечивая мгновенный запуск
и Hot Module Replacement (HMR). Сборка командой npm run build компилирует и
минифицирует код с помощью Rollup в оптимизированную директорию dist.


--------------------------------------------------------------------------------
14. ОГРАНИЧЕНИЯ ПРОЕКТА
--------------------------------------------------------------------------------
- Данные хранятся в памяти браузера / оперативной памяти процессов и сбрасываются
  при перезагрузке (F5).
- Пароли в учебных целях проверяются на клиенте открытым текстом.
- В промышленном приложении авторизация выполняется через JWT/сессии на сервере.

15. ВОПРОСЫ, КОТОРЫЕ МОГУТ ЗАДАТЬ НА ЗАЩИТЕ, И ОТВЕТЫ
--------------------------------------------------------------------------------
В: Зачем нужен Redux Toolkit, если есть useState?
О: useState локален для одного компонента. Когда состояние нужно многим отдалённым
   компонентам (пользователь нужен в Nav, App, страницах), Redux предоставляет
   глобальное хранилище без проброса props через десятки уровней (prop drilling).

В: Что делает createAsyncThunk?
О: Автоматизирует создание трёх типов экшенов: pending (запрос начался),
   fulfilled (запрос успешен), rejected (ошибка). Позволяет декларативно
   управлять индикаторами загрузки и ошибками в extraReducers.

В: Зачем нужны мемоизированные селекторы (createSelector)?
О: Чтобы избежать повторных дорогостоящих вычислений (подсчёт суммы цен,
   фильтрация) при ререндерах компонентов, если сами исходные данные не изменились.

В: Как реализована защита маршрутов?
О: В App.jsx с помощью тернарного оператора:
   element={currentUser ? <HomePage /> : <Navigate to="/login" replace />}

В: Чем удобна библиотека TanStack Table?
О: Она "headless" — берёт на себя сложную математику сортировки, пагинации
   и фильтрации, оставляя полный контроль над вёрсткой и стилями разработчику.
